# IQCN 下载限流与批量选流修复

依据用户提供的 `desktop-run (5).log`（2026-10-10）。此次没有本地构建、类型检查编译、打包或调用线上账号，仅执行 Bun 模拟请求/纯逻辑测试。

## 日志中的问题

- 北京时间20:56–21:10，多项任务在 `download-segment` 收到“操作太频繁”后立即调用 `download-finish`，导致整项任务失败。旧客户端对描述符请求的限流没有等待和有界重试；实际HTTP状态和错误码未记录，不能仅凭文案确认每一次拒绝都来自同一限流器。
- 20:46的批量任务使用四个不同的tvid，但全部携带首集的同一个流vid。当前流ID是单集资源标识，应重新匹配当前集的画质清单，不能跨集直接复用。
- 21:01:46有一次“本地分片还原失败”，旧客户端丢弃了处理模块stderr。仅凭这份日志无法分辨输入、材料、文件写入或具体还原错误，不能宣称还原算法已修复。
- 早期probe/streams的OPERATION_FAILED也缺少后端内部原因；日志后面同一tvid已经能够取到计划，不能据此笼统归因于长期会员失效。GitHub更新403属于独立问题。

## 修改

- 分片取址使用同一GwClient的串行队列，请求启动间隔至少300ms；媒体仍在本机按设置并发下载。当前同一客户端内的任务共享队列；多个App进程不共享内存队列，服务端限流仍生效。
- 只对HTTP429且错误码RATE_LIMITED/CONCURRENCY_LIMITED的分片描述符请求重试，原始计划和索引保持不变。最多初始请求加3次重试；遵守Retry-After，并与1/2/4秒退避取最大值。超过30秒的服务端等待要求停止，不提前重试。取消在下一发请求前生效。
- 不重试streams、登录、配额/IP限制或一般业务错误，不通过取消服务端限流解决问题。
- 含精确流vid的下载任务先probe当前tvid。当前清单仍有该精确选择时保留；否则仅在相同BID/码率/帧率和已知编码条件下只有一个候选时绑定当前vid。缺失或多个候选明确失败，要求单独选择当前集。旧三字段选择维持原语义。
- IQCN失败日志补充受限格式的HTTP状态与错误码。还原模块仅把固定白名单错误映射为原因码，并补充分片序号/字节数；未知stderr内容不进入日志，不保存或打印ticket、identity、URL或任意进程错误。

## 验证与边界

29项Bun测试通过（20项控制队列/选流/客户端/集成模拟，9项已有IQCN选择与本地分片模拟）；跳过运行已安装helper的测试。未运行构建、Go测试、媒体加工工具或线上请求；尚未重新验证用户真实失败的媒体分片。

修改仅在共享客户端层，TUI和Electron共用。未改gateway配额策略、服务器实例或已发布版本标签。新版现场日志仍需用于确认未知OPERATION_FAILED和实际还原失败原因。
