# 爱奇艺国内版下载性能排查

## 2026-10-11：Electron 用户反馈

用户转述：Electron 下载最快不到20 MiB/s，感觉明显慢于官方App。暂无具体用户片源/档位、连接线程数、网卡/磁盘速度和官方App对照测量，不能单凭峰值认定已复现或解决。

当前下载管线：先获取 streams 计划与音轨预检；每片CDN直连写入临时文件，启动一个本地Go进程完成还原，再读回并按序追加视频TS。还原并发固定2，下载并发来自配置（默认4）。界面速度是按序写出的处理后字节数除以下载与处理总时间，并非纯网络吞吐。没有initial URLs的分片还需要串行控制面请求，存在300ms队列间隔；是否触发需实测计划确认。

已确认并修复的调度问题：orderedDownload 原本以 pending.size 限制工作槽位；后续片已完成但首片未完成时，它们仍占槽，阻止新下载。改为独立 active 计数，完成拉取释放工作槽，结果仍占reserved字节预算直到按序写入。保留128MiB默认预算、取消/错误传播与worker清理。

合成对照：12片、4线程、首片300ms、其余45ms、总预算16KiB；原实现417ms，首片完成前未启动窗口之外任务；修正后316ms，首片完成前另启动8片，峰值并发均4。仅证明调度改善，不能外推成用户真实网络提速百分比。

验证：ordered-download、iqcn-local、iqcn-control共17项测试通过；新增首片暂停情况下提前补充工作槽但不突破字节预算的确定性测试。TypeScript检查通过。本轮没有本地打包或发布。

待完成：同一真实授权片源下分开记录取址、网络下载、磁盘写入、进程启动、参数派生与还原耗时；用Electron对应Node路径进行并发对照，确认主瓶颈并验证真实吞吐改善与媒体完整性。不能只凭合成测试宣布下载速度问题完成。

## 配对样本的本机性能证据

从 sandbox-a 只读使用已有 seg.bbts、配对ticket和identity，没有将材料加入仓库。运行已安装的 iqcn-local.exe，计时包含进程启动、参数派生、输入读取、还原与输出写入：2,585,564字节样本三次39/42/41ms（62.79/59.15/60.32MiB/s）；8份拼接20,684,512字节三次198/208/239ms（99.66/94.93/82.41MiB/s）。六次输出均匹配既有测试的golden SHA256。

Node v24 本地HTTP服务器回送同一配对媒体，客户端走生产downloadIQCNLocalSegment、2个处理槽、orderedDownload、磁盘追加，8片共165,476,096字节：1线程2780ms/56.76MiB/s；4线程1317ms/119.86MiB/s；8线程1342ms/117.60MiB/s。每片验证golden哈希。无实际CDN参与，所以不能把这些数值当用户网络速度；只能排除当前电脑本地管线存在固定20MiB/s上限。4到8线程没有改善，不以无限增线程作为解法。

客户端加入onTiming回调，聚合每20片及视频阶段结束输出脱敏性能记录：descriptorMs、networkMs、restoreMs、readMs、descriptorRequests、fetchAttempts、wallMs与线程数。restoreMs包含处理队列等待与helper进程耗时；networkMs包含流式落盘；并发阶段耗时之和不可直接当墙钟时间。记录不含URL、token、处理材料或路径。18项分片/调度/限流测试通过，含阶段计时和敏感信息不泄露测试。尚待真实CDN和用户现场数据验证。

## 真实CDN与逐片取址瓶颈

继续使用本人已有国内版会话/设备取得单集3380828239309300、BID800/BR100/25fps的真实计划。共677片、1,068,344,404字节，只有前98片属于首次调度授权的媒体文件并自带URLs。其余片段需要换文件调度。当前客户端原路径对没有初始URLs的每片都进入串行300ms控制面队列，即使源站调度已取得同一媒体文件的授权，仍需逐片网关往返。

Node同一真实CDN前12片共21,361,688字节：1线程2070ms/9.84MiB/s；4线程338ms/60.31MiB/s；8线程383ms/53.23MiB/s。每次长度校验通过。后续批次可能受缓存/连接预热影响，不能作为用户网络的严格单变量提速比，但证明该CDN在当前网络能超过20MiB/s。

新增download-segment可选batch=1，额外返回relatedSegments（最多128条、URL字符串预算512KiB）。地址仅来自当前源站授权，通过既有SegmentCDNURL校验相同escaped media path并保留各片start/end/contentlength/sd，不跨文件复用。客户端按连接Key/计划短暂缓存，刷新地址时清空该计划、任务结束清理，旧网关无relatedSegments仍兼容；既有QPS退避不移除。

真实第二媒体文件：首次缺地址index98，一次107ms源站调度生成94条（98—191）。抽查98/145/191，CDN均HTTP200，实收1,458,880 / 1,427,484 / 1,556,640字节，匹配对应片长。测试覆盖文件隔离、范围、128条上限、缓存命中、刷新、Key切换、异常元数据和旧网关兼容；20项客户端相关测试通过。

## 整集真实网络对照与完整性

Node v24.21.0 使用同一计划、4个下载槽、2个还原槽，通过生产分片下载和顺序写入代码完成两轮677片下载。控制接口由本机 Go HTTP 服务调用真实 Adapter；媒体直连真实 CDN，本地使用现有 iqcn-local.exe 还原。两轮均保留300ms控制请求队列，使用相同的新调度器，仅切换是否请求批量分片信息。

- 批量取址：6次控制请求，47,838ms，平均21.30MiB/s。
- 旧逐片取址：579次控制请求，183,913ms，平均5.54MiB/s。
- 本次对照吞吐约为3.84倍，墙钟时间缩短约74%。这是单次、先批量后旧流程的顺序对照，仍可能受CDN波动影响。

两轮各输出1,068,344,404字节，每片SHA256及整文件SHA256完全一致。整文件哈希为 `e6f08f3d3beea43ec6b20f6d6677ca928ca40d5cf3f90446f2fd65b172008680`。ffprobe识别HEVC 3840×1608、25fps、AAC，时长2668.971244秒。该检查确认媒体元信息和两轮字节一致性，不等于逐帧解码验收。

证据位于工作区 `work/iqcn-speed-20261011/full-pipeline/results.json`；其中只有脱敏计时及分片哈希。相邻的 `plan.private.json` 含授权材料，不可提交或公开。

此次覆盖共享下载逻辑，但不是完整Electron界面端到端测试，且控制服务为本机回环，并未测量已部署网关的公网延迟；尚无用户原片源及官方App同网对照。因此已验证逐片取址是可消除的瓶颈，不能承诺每位用户达到21.30MiB/s或与官方App等速。批量收益需要配套更新网关和客户端，旧网关仍可用但无法提供该批量收益。本轮仅测试，未本地打包或发布。

## Electron实际运行时复验

使用已安装的Electron 44.4.5（内置Node 24.21.0，版本证据electron-pipeline/runtime.json），以ELECTRON_RUN_AS_NODE=1运行同一共享下载管线；未打包。Go诊断测试增加可选IQCN_PERF_RUNTIME_BINARY环境变量，缺省仍用node。Electron生产路径的iqcn.ts默认媒体fetch同样使用Node全局fetch；网关调用在完整桌面端使用另外的Chromium服务路由，本次回环控制接口没有覆盖该部分。

同一节目重新获得计划，仍677片、1,068,344,404字节，4个下载槽、2个还原槽：批量取址6次、40,681ms、25.04MiB/s；旧逐片取址579次、184,899ms、5.51MiB/s。此轮吞吐约4.55倍，时间缩短约78%。两轮分片哈希一致，批量输出整文件SHA256也与前述系统Node两轮完全相同；ffprobe确认3840×1608 HEVC、AAC及2668.971244秒时长。

## 真实整集并发对照

继续在Electron 44.4.5使用批量取址、2个还原槽和相同节目。8下载槽：22,299ms、45.69MiB/s；紧接着重跑4下载槽：40,365ms、25.24MiB/s。两轮均677片和6次取址，8槽所有分片哈希及完整文件SHA256与既有对照一致。结果分别位于electron-eight-workers和electron-four-workers-control目录。两次采用新建计划，仍可能受CDN实时波动影响，不能视为所有用户的固定倍率。

本机8槽相对于紧邻4槽对照吞吐约1.81倍；旧单片取址的控制面瓶颈解决后，并发度成为另一项实际影响因素。先前仅12片下载和本地HTTP的8槽测试不能代替整集证据，本轮更新该判断：在当前真实整集网络下8槽确有明显收益。

使用配套批量取址网关/客户端的用户，可先将下载线程数从4调整为8再比较同一片源；低带宽或磁盘/CPU受限设备不保证获益。没有擅自修改现有线程配置或全平台默认值，也没有突破128MiB缓冲预算与2个还原槽上限。仍未完成用户原片源与官方App同网对照。
