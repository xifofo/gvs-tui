# IQCN 初始分片地址提速

本机任务8的视频共718段、4,326,814,548字节。日志首尾视频描述符完成时间相差356.208秒，平均约11.58 MiB/s（包含下载、还原和顺序写入，非网卡瞬时速度）。717个间隔中611个小于350ms，中位数306ms，与此前300ms取址队列吻合。

按平均每段大小计算，每段一次300ms取址即约19.16 MiB/s的调度上限；网络/处理开销会进一步降低实测吞吐。增加下载线程无法移除这个瓶颈。

后端`streams`新增可选的`video.segments[].urls`，仅对当前源站授权能映射到同一文件的分片生成地址。客户端直接使用当前计划的这些地址，按用户配置并发；正常分片不经逐段取址队列。跨媒体文件、缺地址的分片保持旧路径，过期地址仍通过原计划与索引刷新，受限流/重试保护。未把签名或拼址算法搬到客户端，没有移除服务端配额控制。

客户端16项模拟测试通过：8个CDN任务能同时到达，无逐段gateway请求；倒序完成仍顺序写入；初始地址403只刷新对应片；索引和长度不匹配拒绝；旧网关无urls数组时继续正常取址。后端新增范围和文件身份回归测试但未本地执行，因为用户要求不本地构建。只运行gofmt和静态差异检查。

需要后端和客户端同时更新才能使用初始地址。旧后端兼容但不获得本项提速。尚未部署新后端或验证实际带宽提升，不承诺跑满；CDN、磁盘和还原处理仍可能成为下一瓶颈。本机配置保持8线程，未修改用户设置或已有视频缓存。
