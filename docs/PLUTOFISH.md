# PlutoFish 二开接入

本仓库的正常终端版和桌面版必须同时通过 GVS 网关与 PlutoFish 鉴权。连接页没有关闭或跳过 PlutoFish 的入口。首次填写两套地址和密钥；再次启动可以沿用本机保存的凭据，但必须重新请求两端验证，不能凭配置文件直接进入。

## 运行与配置

- 终端版：仓库根目录执行 `bun run dev`，正常使用执行 `bun run start`。
- 桌面版：在 `app/` 安装依赖后执行 `bun run dev`。
- PlutoFish 地址填写服务根地址，例如本机开发的 `http://127.0.0.1:15172`；其他地址要求 HTTPS。不要填写 GVS 网关地址或 `/api/v1/publisher/me` 路径。
- 在 PlutoFish 后台“发布端”登记源账号及密钥，使用完整凭据 `pfp_<发布端ID>_<密钥>` 接入。
- 服务端须包含 `GET /api/v1/publisher/me` 接口。后端更新后需重启服务；404 表示地址不正确或服务版本尚未更新，不能作为鉴权通过。
- 两套凭据分别发送给对应服务。PlutoFish 不使用网关代理字段，也不与网关共享会话或 Cookie。

PlutoFish 配置保存在上游 `tui.json` 同目录的 `plutofish.json`，权限为 `0600`。`APPDATA` / `XDG_CONFIG_HOME` 和桌面版 `GVS_PROFILE_DIR` 继续遵循上游的配置目录选择规则。此文件只保存地址和密钥，不保存“已验证”标记。密钥不会进入公开状态、日志或 Git。

已保存密钥的字段留空表示沿用，换服务器必须重新填写。连接失败可以在原页面改正并重试。关闭程序后再次启动时，会重新验证双方。运行中每 60 秒复查 PlutoFish，单次请求超时 8 秒；复查失败锁回连接页，阻止新任务和恢复任务，已有任务记录保留。在运行的下载不会被自动删除或强制终止。再次放行必须重新完成双重验证。

桌面版侧栏显示已验证的 PlutoFish 发布端名称和绑定源账号；点击可进入「设置 → PlutoFish」，查看连接状态、服务地址及源账号名称／别名。收起侧栏后保留身份首字和连接状态点。信息沿用 `/api/v1/publisher/me` 的实时验证结果，仅接受已登记且绑定有效源账号的发布端身份。该页面不展示密钥。

上游的下载器、平台登录、媒体处理和 GVS 配置结构未复制到二开模块中。同步上游后重点核对表中接线位置，尤其不能丢掉启动验证、`configured` 的双重条件、主进程与任务入口检查。`src/runtime.test.ts` 的上游业务夹具显式使用已认证状态，真实强制连接边界由集成模块的测试覆盖。

离线 `preview` / `demo` 保持上游的示例用途，不能据此认定真实鉴权或下载成功。已接入任务资料与进度上报、115 分片上传（V2 与实际旧版响应兼容）和上传成功后的资源登记和自动发布；离线测试不代表真实网盘上传验收。

## 下载任务的发布信息

桌面版「设置 → PlutoFish → 下载完成后自动上传 PlutoFish」默认开启。关闭后，新任务和尚未开始上传的任务保留为手动上传，已开始上传的文件继续完成。重新开启仅对之后新加的任务生效；已有等待任务仍需逐个点击「立即上传」，等待状态随任务保存，重启不会自动放行。关闭时下载页隐藏发布信息和版本选择，入队不要求分类、不查询已有版本、不创建网盘目录；成品保留本地，之后可在任务中选择分类并点击「补全并上传」。

下载后在本机改名或移动视频，可在下载任务的上传面板点击「重新选择文件」，选择改名后的原视频。确认页面显示新文件名和路径，重新检测实际媒体规格；文件名包含明确单集 `SxxExx` 时回填季集号，关闭自动上传期间创建且尚未补全发布信息的任务可确认或修正这些数值，支持 `S00` 与集号 `0`。确认关联只更新任务、本地发布清单和下载历史，不启动下载或上传；之后点击「补全并上传」或「立即上传／继续上传」，115 和资源登记均使用新文件名。取消选择不改变任务，重启保留已确认的新路径。已有上传断点或已完成上传的任务不能通过此入口替换文件；尚未上传但已固定发布信息的任务保持原季集号。

桌面版开启自动上传时，在画质页的「PlutoFish 发布信息」选择资源分类，分类来自已验证身份的 `categories`，只包含后台启用的选项。分类为必填项，未选择或已失效时不能开始下载、补传或保存订阅设置。旧连接快照没有选项时自动重新读取身份，也可点击分类旁的「刷新」；加载中、读取失败、服务未返回分类和后台无启用分类分别显示状态。可沿用 TMDB 匹配或手动指定当前电影／剧集类型的 TMDB ID；季号沿用现有输出季号设置，集号可逐集确认，支持特别篇 0。命名与发布信息使用同一季／集号。终端版在下载确认页按 `C` 切换分类，TMDB 与季号沿用原有选择流程。

没有 TMDB 时使用平台作品 ID，并上报平台名称、海报 URL 和简介；桌面端开启自动上传时必须选择当前有效的资源分类才能创建下载任务，避免下载后静默跳过上传；分类来自当前服务，不能自动猜测。旧版已下载但缺少分类的任务显示在「待处理」，选择分类并点击「补全并上传」后直接上传现有成品，并记住分类供后续订阅使用。尚未开始上传的草稿在补全分类时生成对应的发布身份；已进入上传流程的任务不能更改身份。终端端缺少必要信息时仍保留待补全草稿。桌面端在「PlutoFish 发布信息 → 115 上传目录 → 选择目录」中浏览绑定源网盘，支持上一级、路径导航、分页、刷新与空目录选择；默认根目录。下载设置页的目录弹窗还可点击「创建并选择」，在当前网盘目录下创建输出预览中的作品/季目录；复用已有同名文件夹，成功后自动选中最终目录，手动年份和季号同步生效。创建失败不改变原选择，重试会从已存在层级继续。选中后显示完整路径，任务保存字符串目录 ID 和路径快照；上传仍按 ID 定位。换绑时清除旧目录选择，入队后目录固定；终端端默认根目录。选择有效分类及绑定源账号后，成品检测成功便进入上传队列。服务端未升级、不返回 `categories` 时会明确提示，不硬编码分类。

桌面端匹配 TMDB 成功后，「上传目录」下会显示「在网盘创建文件夹」按钮。选择分类后点击按钮，先在弹窗中浏览并选择上级目录，核对完整创建路径，再点「确认创建」，按 `分类/作品 {tmdbid-ID}/season 01` 创建；电影省略季目录，特别篇使用 `season 00`。创建成功回填最终目录 ID 和完整路径，已有同名目录复用。表单保存、入队和上传均不会自行触发建目录。

成功后按钮显示「文件夹已创建」，本机偏好记住原父目录及作品目录 ID；重开表单、修改标题或分类不会重新套目录。同作品换季后，弹窗默认定位到原作品目录 ID，只追加新季，避免新译名生成另一套作品文件夹。若在弹窗中明确改选其他上级目录，完整预览会切换为该位置下的分类／作品／季，确认后严格按新位置创建。浏览或取消不改变上传目录和创建记录；创建失败保留弹窗中的上级目录，可核对后在原处手动重试，不自动重试。重新手选不同上传目录会清除这条创建记录。

入队前生成并保存 `releaseKey` 和 `fileKey`，同一绑定、作品、季、平台、画质和音轨选择的分批剧集共享版本身份，每个视频文件单独标识。暂停、重试、重启不会重新生成；不同服务器、发布端或源账号不会共用身份。不同季、版本或目录选择得到不同标识。发布草稿中只保存脱敏的绑定信息，没有发布密钥或下载 URL。

桌面版按「TMDB 作品 + 平台」记住资源分类和 115 目录，无 TMDB 时按平台作品 ID 保存；同时隔离服务器、发布端、源账号和电影／剧集类型。选择分类、目录后立即保存，下次选其他集或重启程序时自动回填；手动指定的 TMDB 和季号也会沿用，单集修正不复制到下一集。文件保存在 `tui.json` 同目录的 `plutofish-publication-preferences.json`，权限为 `0600`，不含凭据。首次读取时可从本机现有下载任务迁移最近的设置，后续修改优先于旧任务。

订阅的新集自动下载、洗版统一读取这份作品设置，订阅编辑页可查看、修改分类、目录和 TMDB；点「保存」生效，取消不改动。换目录影响后续创建的任务，已入队的任务继续使用原目录快照。开启自动上传时，分类失效会暂停创建新下载任务并提示重新选择；无绑定账号的旧任务仍按待补全处理，不自动套用其他账号的目录。115 上传会把视频文件直接放进选中的目录，不再创建预览中的剧名／季子目录；文件名预览中的目录是本地下载结构；「在网盘创建文件夹」旁的预览则是本次明确创建的网盘相对路径。

订阅检查发现新集后先记为「待下载」，只有成功加入下载或确认本机下载历史已有才算处理完。分类失效、发布端或源账号改变、版本未匹配、取链失败，或规则组暂时没有满足的画质时，这一集保持「待重试」，订阅卡片显示集号和最近一次原因；按 10、20、40、80 分钟、之后每 2 小时重试，首次失败通知一次。下次检查不晚于最早的重试时间，按播出窗口或上线时间检查的订阅也能及时补下。旧版本会把这类新集记成已见过后不再处理，之前漏下的集由下文的 PlutoFish 进度同步补回。

追更进度以 PlutoFish 为准，不只看本机记录。订阅首次检查、有待下载的集、手动「立即检查」，或距上次核对满 6 小时时，按入队时同样的作品、季和版本匹配规则查 `releases/query`，读取匹配版本的 `episodes`（已就绪集号）：版本里已有的集记为「不用再下」（例如另一台电脑或另一个 115 账号已经上传），订阅前已上线但版本里缺的集从版本第一集起补下，例如版本已有第 1–3、5 集时补下第 4 集；还没有对应版本时保持原来的只追新集。订阅记住同步到的版本，之后的版本查询和入队都带上它：绑定和唯一规格都没对上时（换 115 源账号后发布标识会变）沿用这个版本，已下架或不在候选里则不沿用。同一 115 账号在不同电脑上的发布标识相同，重复上传会被服务端识别为同一文件。旧服务端不返回 `episodes` 时只把不超过 `latestEpisode` 的集视为已有，不补中间缺的集。

换 115 源账号后订阅自动接上：原账号已从发布端移除或停用、发布端改用新的默认源账号，而新账号还没有这部作品的偏好时，订阅自动下载沿用这部作品最近一次任务的分类、TMDB 和季号，在新账号里按原路径从根目录逐层确保上传目录（服务端按 mkdir -p 创建，已有同名目录直接复用，每次最多 4 层），并保存为新账号的作品偏好；版本按上文沿用订阅记住的版本，追更进度照常从 PlutoFish 读取。同一账号只是别名变了时直接沿用原目录 ID。原账号仍可用时不沿用，不把作品静默改投其他账号；分类已失效、没有以前的任务或建目录失败时，这一集保持待重试，订阅卡片显示原因，可在订阅编辑里重新选择。核对进度只借用作品和季，不建目录。手动下载仍按页面选择。

桌面版的 `jobs.json` 保存完整任务；两端还会在 `tui.json` 同目录的 `plutofish-publications/` 写入独立清单（文件权限 `0600`）。清空任务列表不会删除清单；重复下载在实际完成前保留上次成品清单。终端版原有下载列表不支持跨进程恢复；已下载的发布成品在重新认证后恢复到任务列表，支持继续上传。

下载列表区分下载与上传：下载结束后，上传任务继续留在「进行中」并保持展开；显示上传百分比、已发送字节／总大小、近五秒平均速度、预计剩余时间、账号共享上限，以及文件校验／网盘核验／资源登记阶段和失败原因。分片内发送进度每 500 毫秒刷新，暂停、核验或完成后清除速度；续传断点和服务端上报仍只采用远端已确认分片。支持暂停、继续和失败重试。只有上传与登记完成才计入「已完成」；「清除已完成」保留待补全、暂停和失败的成品。

共享发布引擎最多同时上传两个文件，另以一个预处理槽提前校验两个排队成品；下载和媒体处理继续按原队列运行。上传复用 HTTPS 连接、提前读取下一片并只算一次分片 MD5；SHA1 仅在本进程内按完整文件身份缓存，变更或重启后重算。单个文件仍顺序上传，两路上传和暂停、续传、退出分别管理，不把一次失败扩散到另一路。

新上传任务默认每片 16 MiB；大文件自动增大分片，确保不超过 10,000 片。已有断点任务沿用清单中记录的分片大小。

连接和后台重验读取 `publisher/me.capabilities.uploadClientGrouping`，仅显式 `true` 时使用 `uploads/prepare.clientId` 与 `credentials.rateScope` 启用双路上传；未声明、关闭或未知能力时以单文件旧协议上传，其他文件仍可提前准备，并显示兼容模式提示。更高版本的未知能力不会阻断连接。当前上传的所有请求保持原协议，等其结束后再切换；不因普通 422 盲目删字段重试。旧客户端连接新版服务端继续按单任务互斥工作。进程级 UUID 将同一客户端的两个任务纳入同一账号租约组；另一个进程或旧客户端使用同账号时排队。账号速率由两路流共同分配，单任务可使用全部空闲额度；同一 115 用户的多个源配置由 `rateScope` 合并，不能给每条连接各自分配完整上限。每片发送前检查凭据，距上次获取满一分钟时重新获取并更新速率，上传地址与续传标识继续使用服务端返回值。无需新增数据库迁移。监控工具通过 `sync-publisher.mjs` 同步这份引擎，不能直接编辑其 vendor 快照。

macOS 对已复现的 E-AC-3 指数解码兼容错误（开头 `exponent -1`，稍后 `exponent 28`）先完整执行 CRC 检查，再由系统 AudioToolbox 完整解码并核对时长；只在错误类型、次数均符合已知样本且两轮检查通过后保留原始音频包封装。CRC 损坏、额外解码错误、系统解码失败或时长不符仍会停止，不通过连续删帧或转码规避检查。

下载成功后把已有成品检测的分辨率、编码、动态范围、音轨和实际文件大小写入清单。申请 4K 而实际检测为 1080p 时保留实测 1080p；检测缺失时标为「媒体规格待检查」，不从申请档位补造。下载页可展开信息核对作品、分类、季集、绑定、标识和实际规格。未探测出实际规格的文件不会上传；上传完成并通过远端核验后，资源登记与草稿版本自动发布同事务完成，无需后台再点发布。管理员已手动下架的版本保持下架。

版本名从最终文件名中提取分辨率起的规格段，保留原有大小写；剧集前加 `S01` 等季号，排除片名、年份、集号、单集标题、发布组和扩展名。例如 `Good.Night.2026.S01E01.360p.YOUKU.WEB-DL.HEVC-FPWeb.mp4` 对应 `S01.360p.YOUKU.WEB-DL.HEVC`，带 SDR 的新文件则保留 `.SDR.`。分辨率字段使用 `360p` 等档位；没有规格段的简短平台文件名才回退到已探测规格，并与成品命名共用编码标签。版本展示名不替代稳定 `releaseKey`，已入库版本资料仍由管理员明确修改。

## 发布版本选择

开启自动上传后，桌面端“发布与保存”显示当前规格及同作品、同季的已有版本；普通季额外列出该作品的 S00 特别篇。选择 S00 后同步切换命名季号并重新查询、保留所选版本，发布集号仍需按实际内容确认；不会按标题“加更”等字样自动换季。订阅匹配和默认推荐仍只使用当前季，入队会重新验证版本与季号一致。默认优先选择此前绑定的版本；没有绑定时，仅在规格候选唯一时自动勾选。`YK/YOUKU`、`H265/HEVC` 等别名统一比较；多个可能匹配的候选需手选，已下架版本不按规格自动推荐。

版本规格解析、来源标签及候选匹配与 PlutoFish Watch 共用同一实现，兼容旧名称缺失音轨标签，但不忽略已知的音轨、帧率、来源类型或特殊规格差异。成品命名共用媒体标签：HLG 明确写作 `HLG`，48fps 及以上保留帧率；旧 HLG 版本的泛 `HDR` 名称可根据目录内已确认的 HLG 元数据匹配。下载器从下载任务确定平台与 `WEB-DL` 类型；Watch 从文件名或用户预设获得来源，来源缺失时待确认。

下载前画质目录未提供明确视频编码时（例如腾讯只有数字 `profile: 4`），预览保留缺失字段，按其余规格和制作组寻找唯一候选；候选自身必须有明确编码。缺少声道也可兼容，已经明确的编码、音轨、声道、动态范围等差异仍会阻止匹配，同组存在多个可能版本时仍需手选。例如 `S01.2160p.TX.WEB-DL.MAXPLUS.HDR.60fps.DDP-WF` 可唯一匹配 `…DDP.5.1.H.265-WF`。该规则只用于下载前选版，不把候选规格写作成品实测证据；Watch 成品匹配继续要求明确视频编码。

本批包含第 1 集、或电影没有匹配版本时可自动新建。续集（包括集号 0）未找到唯一匹配版本时，必须选择已有版本或“强制新版本”后才能开始；可以手动选择规格不同的已有版本。查询错误会保留错误并阻止开始，不当作空列表。改作品、季号、集号、画质、音轨或发布账号后重新匹配，旧响应不覆盖新结果。

候选来自 `POST /api/v1/publisher/releases/query`，只读 PlutoFish 本地目录，不访问 115。主进程入队前重新查询和验证；显式选择随草稿持久保存，完成上报传 `releaseTarget.existingReleaseId`。强制新版本在主进程为本批生成独立标识，同批各集共用，重启/重试保持不变；再次手动强制新建会产生另一个版本。此选择不会合并已有历史版本。后端需包含 `00034_publisher_release_aliases.sql` 迁移；旧服务未提供查询接口时无法使用桌面发布选择。

离线验收：`bun test src/integrations/plutofish`；在 `app/` 运行 `bun run typecheck`、`bun run build`，再执行 `bunx vite build --config scripts/release-picker-smoke.config.ts` 和 `node_modules/.bin/electron ../.build/release-picker/smoke.cjs`。界面验证使用模拟目录、临时配置和禁止网络的 Electron 窗口，不代表真实下载或 115 验收。

## 任务上报与断点续传

入队、下载、处理、上传、暂停、失败、取消与完成使用独立 `tasks/report` 快照上报，后台「发布任务」按权限查看资料及下载/上传进度。下载百分比来自下载器事件；上传百分比仅计已确认分片字节。未知成品大小填 0，不把下载器分片大小当成最终文件大小。

快照和断点保存在 `plutofish-publications/*.state.json`，先原子保存再发送，网络恢复后重放最新序号。失败后可在桌面端点击「继续上传 / 重试上报」；终端任务页 `P` 暂停发布、`U` 继续发布。退出保留断点，重启通过双重鉴权后继续原上传。暂停/失败保留远端分片；取消仅停止当前任务，不删除用户网盘文件。

目录列表通过 `POST /api/v1/publisher/directories` 获取：桌面主进程发送发布端 Bearer，PlutoFish 验证当前绑定源账号后使用服务端保存的 115 Token 读取文件夹，返回名称、ID、祖先路径与分页游标，长期 Token 不进入渲染进程。每次请求前后复查发布端和账号版本；只接受登记发布端的完整凭据，且只能访问绑定的源账号。目录读取会通过服务端统一入口刷新临期凭据，刷新失败时提示在 PlutoFish 后台重新授权；失败可重试或返回根目录，不自动采用旧结果。

115 调度由服务端使用发布端绑定的源账号执行。下载器只取得临时 OSS 凭据，长期网盘 Token 不下发，临时凭据不写入清单。V2 按官方文档使用本次任务的完整 endpoint，不重复拼接 bucket。2026-10-15 实测旧版调度仍可能返回空 file_id 且缺少 endpoint；此时先保存 pick_code，再从临时凭据读取 OSS 区域地址，由 SDK 按区域地址拼接 bucket，不写死上传主机。分片初始化携带 sequential，之后串行发送，以便 115 的合并回调读取完整 SHA1。保留原 pick_code/uploadId，通过 ListParts 核对分片并校验 Content-MD5/ETag；Complete 的 HTTP 200 还须检查回调 state，最终仍由服务端核验文件身份；令牌接近过期或超过 60 秒时刷新凭据/速率。`transfer_config.rate` 换算为 OSS bits/s 限速，同一网盘用户由服务端占用锁串行上传，20 秒续约，失联 240 秒后释放；这不协调 PlutoFish 外部客户端的上传流量。

Complete 回执丢失时先按原任务核验网盘文件大小和 SHA1。115 的原上传任务码可能不同于完成文件取件码；服务端仅从任务绑定目录中核对唯一同名、同大小、同 SHA1 的完整文件，再通过真实取件码复核，返回独立的 filePickCode 供资源登记，不改用于续传的 pickCode。仅针对旧版未启用 sequential 的已合并断点：服务端明确返回文件尚未就绪、且 OSS 明确返回 NoSuchUpload 时，保留旧 uploadId 供追溯，沿用原 pick_code/object 创建顺序分片会话；普通网络故障和核验错误不能触发迁移。目录登记失败可以单独重试，不重复上传成品；最终登记携带 `releaseTarget.autoPublish=true`，就绪主视频自动发布草稿；重复上报不重复发布，也不恢复管理员已下架的版本。当前完成链只处理任务的主视频文件，独立外挂字幕仍走原文件上报契约。

协议依据：[115 上传流程](https://open.115.com/doc/115开放平台/API列表/文件管理/文件上传/上传流程.md?raw=true)、[获取上传凭证](https://open.115.com/doc/115开放平台/API列表/文件管理/文件上传/获取上传凭证.md?raw=true)、[文件上传](https://open.115.com/doc/115开放平台/API列表/文件管理/文件上传/文件上传.md?raw=true)、[断点续传](https://open.115.com/doc/115开放平台/API列表/文件管理/文件上传/断点续传.md?raw=true)（2026-10-15 读取，文档最后修改于 2026-09-14），以及 [ali-oss SDK](https://github.com/ali-sdk/ali-oss) 和 [OpenList 的 115 顺序分片实现](https://github.com/OpenListTeam/OpenList/blob/main/drivers/115_open/upload.go)。

### 上传后的订阅分段校验

发布清单在上传完成后继续保留。客户端用独立收件循环向 PlutoFish 的 `publisher/range-proofs/pending` 领取待办，不再按每批 50 条轮转上传历史，也不会阻塞上传和快照同步。首次请求不传等待参数；服务端响应 `waitSupported: true` 后，空首页请求携带 `waitSeconds: 25`，有新挑战时提前返回，最长等待 25 秒。每页最多 100 个挑战，有 `nextCursor` 时携带 `after` 立即翻页，处理后续接等待。旧服务端或通知连接不可用时保持 15 秒轮询。断线会重连并从持久化待办补领，关闭客户端会取消等待；本地不可用且尚未处理的待办不会反复立即查询。只对实际待办查找最新本地成品，读取最多 8 MiB 的范围计算 SHA1，经 `report` 回传，不向源账号请求 115 下载地址。服务端不保存跨任务摘要缓存；进行中任务自己的校验结果仍独立保存供续办。

每个发布端最多并行处理两个本地校验任务，回执也占用该名额，避免网络慢时不断堆积摘要。同页同内容同范围共享正在计算的结果；同一成品的所有校验任务结束后才能清理清单。任一回执失败时停止领取本页后续任务，等待已开始任务结束，下一轮仍从未确认的这一页继续。

服务端优先使用发布端校验，本地不可用后尝试 ED2K 云下载，源 115 片段读取最后兜底；续办可使用本任务已保存的摘要。服务端同一数据库下全部实例、源账号合计最多两个片段补算，覆盖取得下载地址、读取响应体和计算摘要；满额时持久化原挑战排队，名额空出后自动订阅任务续办，不把繁忙当失败，不重新初始化。发布端最多优先等待 30 秒；明确回报本地不可用后可提前进入 ED2K 云下载或最后的片段兜底。无需长期保留成品；本机清单已删除也能回报不可用，同绑定下相同内容的其他成品可复用。恢复原路径文件但 mtime 改变时，先重算完整 SHA1 验证身份。实际待办拥堵或网络、计算过慢仍可能超时。校验回传不重新上传成品，断线重放摘要幂等；挑战过期或明确失败后需用户重试。服务端需包含迁移 32、36、37、38、39、40 和待办分页、本地成品清理接口；先更新全部服务实例再更新客户端，服务端仍兼容旧版 taskKeys 查询。长轮询自身无需新增迁移，源补算并发控制需要迁移 40；反向代理读取超时应大于 35 秒，发布端仍主动连接服务器，无需公网入口。验证使用离线协议与隔离数据库，不包含真实 115 调用。

本地成品删除后，发布器会清理已经完成且完成快照获服务器确认的发布清单。每个 worker 周期最多检查 50 个路径，每轮间隔一分钟复查；校验发现缺失时优先检查。仅在文件明确不存在且父目录仍可访问时，经 `range-proofs/forget` 撤销服务器的本地校验资格，再删除对应 `.json` 和 `.state.json`；断网、回执不确定或删除失败保留记录供重试。未完成上传、未确认完成快照、权限错误和挂载目录暂不可访问均不清理。上传历史、网盘文件和正在续办的挑战不受影响；之后不再等待这个已删成品。下载历史中的已完成条目不会在重启时重新创建已清理的发布清单。


## ED2K 与本地成品保留

最终成品完成封装和命名后，发布端将 ED2K 计算放入独立后台队列，每个发布端最多同时计算一个；上传、资源登记和订阅交付不等待 ED2K。桌面端与下载历史共用计算线程和按文件身份匹配的本地摘要，避免重复计算。计算时同一遍读取同时得到 SHA1，确认与上传资源相符后，通过 `POST /api/v1/publisher/files/ed2k` 补记资源；只保存链接，不做 115 云下载验证。服务端尚未升级或补记失败时保留文件并重试。

桌面下载任务显示 ED2K 等待计算、实际读取字节百分比、已生成或计算失败；生成后可复制链接。自动发布无需开启下载完成钩子即可显示进度。百分比与上传进度独立，已生成不表示服务端保存成功或云下载可用；保存重试复用已生成的链接。另行展示“ED2K 已保存到服务器”、计划删除时间及延期原因（尚未生成/保存、文件占用、文件改变、清理失败、配置不可读或自动删除关闭）。文件实际删除后，先将“本地文件已删除”同步到下载历史，再清理发布清单；手动删文件也遵循此顺序，历史落盘失败保留清单重试。退出时尚未算完的文件下次重新排队计算，已保存的摘要则恢复为已生成。

桌面设置的 **PlutoFish → 本地成品保留** 默认 24 小时，从上传并登记资源成功后计时；0 关闭自动删除，允许 1–8760 小时。TUI 共用配置目录内的 `plutofish-retention.json`，格式为 `{"hours":24}`。配置损坏时停止自动清理。

到期仍须满足完成快照已确认、ED2K 已生成并获服务端保存回执、路径仍指向原普通文件、应用内部没有校验或 ED2K 读取占用。先停止新本地校验，再等待已开始的任务释放；文件改变、被替换或符号链接一律不删除。检查按分钟分批运行，应用退出期间不执行删除，下次启动续办。旧清单没有发布完成时间时，从升级后首次恢复起算，避免升级立即删除历史文件。

只删除已登记的本地视频，不递归删除目录、字幕或 NFO。删除后沿用本地缺失回执清理发布清单；断网保留清单重试。资源 SHA1、大小、ED2K、源 115 定位及进行中的转存挑战保持不变。外部播放器不属于本应用的占用跟踪范围。服务端迁移 45 接入 ED2K 云下载交付：本地不可用后优先提交到接收用户的指定目录，跟踪原云下载任务，明确失败后才读取源网盘片段。保留时间届满不表示 ED2K 已验证可用；下载完成后的目标文件核验属于实际交付确认，不额外发起可用性探测。


## 多个 115 上传账号

新版服务端身份返回 `sourceAccounts` 授权集合及各账号的平台标识，`sourceAccount` 保留为默认账号。下载设置和订阅编辑的「PlutoFish 发布信息」新增上传账号选择；每部作品记住所选账号，各账号分别保存分类和目录。切换账号先清空旧目录，再读取新账号的偏好，没有偏好时从根目录开始；版本候选随目标重新查询。终端入口未指定账号时仍使用默认账号。

创建任务时固定账号 ID、别名和目录，任务详情及上传进度显示实际目标。默认账号变化不影响仍获授权的历史任务；账号被撤销时拒绝续传，不改投默认账号。账号级拒绝不锁死其他账号的连接。作品已记住的账号被撤销时需要显式重新选择，不自动覆盖保存的偏好。

当前每个任务只选择一个 115 账号，其他网盘平台和一份文件同时分发多个目标尚未接入。升级需要先应用服务端迁移 `00051_publisher_sources.sql` 并更新管理后台；旧单账号服务端和旧发布草稿仍按原绑定工作。

### 文件名识别与影视分类

桌面端进入「选画质 → 发布与保存 → PlutoFish 发布信息」后，首次空白草稿自动用命名预览中的文件名调用 `POST /api/v1/publisher/tmdb/recognize`。请求固定到所选上传账号；TMDB Key 和分类规则由 PlutoFish 服务端管理。可手动修改文件名再次识别。只有服务端明确允许自动回填，且识别期间草稿未变化，才填入作品、TMDB ID、类型、分类、年份和季号；已有信息需要点击「替换当前作品信息」。平台集号不因样本文件名被批量覆盖。

识别后的作品、分类和季号参与命名预览、版本查询、保存偏好及下载入队。需要确认时展开候选列表，可查看原名、年份、类型、TMDB ID、分类和冲突信息，选中后点击“确认并填入”；候选被截断时显示提示。剧集确认区可核对或填写季号（特别篇为 0），缺少季号或多季范围不会默认采用旧季号，须填写单一季号后确认。分类未匹配或已失效时留空，选择有效分类后才能继续。下载页与订阅编辑页共用此流程，不修改平台集号。

切换上传账号或作品后忽略旧响应；已保存偏好优先恢复，不重复自动识别。订阅编辑也提供手动文件名识别。旧服务端或上游故障保留手动分类和 TMDB ID 入口。

终端版选完画质后使用待下载文件名自动识别，确认页按 `R` 可输入文件名重新识别并替换待下载作品与分类，按 `C` 继续手动选择分类。识别不读取媒体、下载文件或访问网盘。

本地验证：`bun test src/integrations/plutofish/recognition.test.ts`；桌面端在 `app/` 构建当前渲染页面并执行 `pnpm exec vite build --config scripts/recognition-smoke.config.ts` 后，使用 Electron 运行 `../.build/recognition/smoke.cjs` 验证真实 Core 与回环协议。附加 `--ui` 自动验证下载页和订阅编辑的候选确认，`--interactive` 打开隔离 UI，`--narrow-dark` 使用窄窗口与暗色；测试文件名前缀 `Slow`、`Ambiguous`、`Old` 分别模拟慢响应、歧义和旧服务端。测试不读取真实配置或调用网盘。

### 115 请求去重

服务端返回已就绪回执后直接登记文件，恢复时已核验成功也不重复发送 `verify`。新 OSS 会话跳过 `ListParts`，续传才查询已有分片。115 限流、文件搜索不完整及未知网盘业务拒绝停止自动重试；临时凭据的账号共享与限流冷却由服务端统一执行。
