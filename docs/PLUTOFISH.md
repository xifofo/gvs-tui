# PlutoFish 二开接入

本仓库的正常终端版和桌面版必须同时通过 GVS 网关与 PlutoFish 鉴权。连接页没有关闭或跳过 PlutoFish 的入口。首次填写两套地址和密钥；再次启动可以沿用本机保存的凭据，但必须重新请求两端验证，不能凭配置文件直接进入。

## 运行与配置

- 终端版：仓库根目录执行 `bun run dev`，正常使用执行 `bun run start`。
- 桌面版：在 `app/` 安装依赖后执行 `bun run dev`。
- PlutoFish 地址填写服务根地址，例如本机开发的 `http://127.0.0.1:15172`；其他地址要求 HTTPS。不要填写 GVS 网关地址或 `/api/v1/publisher/me` 路径。
- 推荐在 PlutoFish 后台“发布端”登记源账号及密钥。具名凭据格式为 `pfp_<发布端ID>_<密钥>`；同时兼容旧的 `publisher.apiKey`，兼容身份没有固定源账号绑定。
- 服务端须包含 `GET /api/v1/publisher/me` 接口。后端更新后需重启服务；404 表示地址不正确或服务版本尚未更新，不能作为鉴权通过。
- 两套凭据分别发送给对应服务。PlutoFish 不使用网关代理字段，也不与网关共享会话或 Cookie。

PlutoFish 配置保存在上游 `tui.json` 同目录的 `plutofish.json`，权限为 `0600`。`APPDATA` / `XDG_CONFIG_HOME` 和桌面版 `GVS_PROFILE_DIR` 继续遵循上游的配置目录选择规则。此文件只保存地址和密钥，不保存“已验证”标记。密钥不会进入公开状态、日志或 Git。

已保存密钥的字段留空表示沿用，换服务器必须重新填写。连接失败可以在原页面改正并重试。关闭程序后再次启动时，会重新验证双方。运行中每 60 秒复查 PlutoFish，单次请求超时 8 秒；复查失败锁回连接页，阻止新任务和恢复任务，已有任务记录保留。在运行的下载不会被自动删除或强制终止。再次放行必须重新完成双重验证。

桌面版侧栏显示已验证的 PlutoFish 发布端名称和绑定源账号；点击可进入「设置 → PlutoFish」，查看连接状态、服务地址及源账号名称／别名。收起侧栏后保留身份首字和连接状态点。信息沿用 `/api/v1/publisher/me` 的实时验证结果；兼容发布密钥明确显示未绑定，不将发布端身份当作管理员用户。该页面不展示密钥。

离线 `preview` / `demo` 保持上游的示例用途，不能据此认定真实鉴权或下载成功。已接入任务资料与进度上报、115 分片上传（V2 与实际旧版响应兼容）和上传成功后的草稿目录登记；离线测试不代表真实网盘上传验收。

## 下载任务的发布信息

桌面版在画质页的「PlutoFish 发布信息」选择资源分类，分类来自已验证身份的 `categories`，只包含后台启用的选项。分类为必填项，未选择或已失效时不能开始下载、补传或保存订阅设置。旧连接快照没有选项时自动重新读取身份，也可点击分类旁的「刷新」；加载中、读取失败、服务未返回分类和后台无启用分类分别显示状态。可沿用 TMDB 匹配或手动指定当前电影／剧集类型的 TMDB ID；季号沿用现有输出季号设置，集号可逐集确认，支持特别篇 0。命名与发布信息使用同一季／集号。终端版在下载确认页按 `C` 切换分类，TMDB 与季号沿用原有选择流程。

没有 TMDB 时使用平台作品 ID，并上报平台名称、海报 URL 和简介；桌面端必须选择当前有效的资源分类才能创建下载任务，避免下载后静默跳过上传；分类来自当前服务，不能自动猜测。旧版已下载但缺少分类的任务显示在「待处理」，选择分类并点击「补全并上传」后直接上传现有成品，并记住分类供后续订阅使用。尚未开始上传的草稿在补全分类时生成对应的发布身份；已进入上传流程的任务不能更改身份。终端端缺少必要信息时仍保留待补全草稿。桌面端在「PlutoFish 发布信息 → 115 上传目录 → 选择目录」中浏览绑定源网盘，支持上一级、路径导航、分页、刷新与空目录选择；默认根目录。下载设置页的目录弹窗还可点击「创建并选择」，在当前网盘目录下创建输出预览中的作品/季目录；复用已有同名文件夹，成功后自动选中最终目录，手动年份和季号同步生效。创建失败不改变原选择，重试会从已存在层级继续。选中后显示完整路径，任务保存字符串目录 ID 和路径快照；上传仍按 ID 定位。换绑时清除旧目录选择，入队后目录固定；终端端默认根目录。选择有效分类及绑定源账号后，成品检测成功便进入上传队列。服务端未升级、不返回 `categories` 时会明确提示，不硬编码分类。

入队前生成并保存 `releaseKey` 和 `fileKey`，同一绑定、作品、季、平台、画质和音轨选择的分批剧集共享版本身份，每个视频文件单独标识。暂停、重试、重启不会重新生成；不同服务器、发布端或源账号不会共用身份。不同季、版本或目录选择得到不同标识。发布草稿中只保存脱敏的绑定信息，没有发布密钥或下载 URL。

桌面版按「TMDB 作品 + 平台」记住资源分类和 115 目录，无 TMDB 时按平台作品 ID 保存；同时隔离服务器、发布端、源账号和电影／剧集类型。选择分类、目录后立即保存，下次选其他集或重启程序时自动回填；手动指定的 TMDB 和季号也会沿用，单集修正不复制到下一集。文件保存在 `tui.json` 同目录的 `plutofish-publication-preferences.json`，权限为 `0600`，不含凭据。首次读取时可从本机现有下载任务迁移最近的设置，后续修改优先于旧任务。

订阅的新集自动下载、洗版统一读取这份作品设置，订阅编辑页可查看、修改分类、目录和 TMDB；点「保存」生效，取消不改动。换目录影响后续创建的任务，已入队的任务继续使用原目录快照。分类失效时桌面端暂停创建新下载任务并提示重新选择；无绑定账号的旧任务仍按待补全处理，不自动套用其他账号的目录。115 上传会把视频文件直接放进选中的目录，不再创建预览中的剧名／季子目录；预览目录是本地下载结构。

桌面版的 `jobs.json` 保存完整任务；两端还会在 `tui.json` 同目录的 `plutofish-publications/` 写入独立清单（文件权限 `0600`）。清空任务列表不会删除清单；重复下载在实际完成前保留上次成品清单。终端版原有下载列表不支持跨进程恢复；已下载的发布成品在重新认证后恢复到任务列表，支持继续上传。

下载列表区分下载与上传：下载结束后，上传任务继续留在「进行中」并保持展开；显示上传百分比、已确认上传字节／总大小、文件校验／网盘核验／资源登记阶段，以及可见的失败原因。进度按已确认分片更新，支持暂停、继续和失败重试。只有上传与登记完成才计入「已完成」；「清除已完成」保留待补全、暂停和失败的成品。

下载成功后把已有成品检测的分辨率、编码、动态范围、音轨和实际文件大小写入清单。申请 4K 而实际检测为 1080p 时保留实测 1080p；检测缺失时标为「媒体规格待检查」，不从申请档位补造。下载页可展开信息核对作品、分类、季集、绑定、标识和实际规格。未探测出实际规格的文件不会上传；上传完成后显示「已上报草稿目录」，仍需后台审核发布。

## 任务上报与断点续传

入队、下载、处理、上传、暂停、失败、取消与完成使用独立 `tasks/report` 快照上报，后台「发布任务」按权限查看资料及下载/上传进度。下载百分比来自下载器事件；上传百分比仅计已确认分片字节。未知成品大小填 0，不把下载器分片大小当成最终文件大小。

快照和断点保存在 `plutofish-publications/*.state.json`，先原子保存再发送，网络恢复后重放最新序号。失败后可在桌面端点击「继续上传 / 重试上报」；终端任务页 `P` 暂停发布、`U` 继续发布。退出保留断点，重启通过双重鉴权后继续原上传。暂停/失败保留远端分片；取消仅停止当前任务，不删除用户网盘文件。

目录列表通过 `POST /api/v1/publisher/directories` 获取：桌面主进程发送发布端 Bearer，PlutoFish 验证当前绑定源账号后使用服务端保存的 115 Token 读取文件夹，返回名称、ID、祖先路径与分页游标，长期 Token 不进入渲染进程。每次请求前后复查发布端和账号版本；不接受管理员 Cookie、兼容发布密钥或其他源账号。目录读取不隐式刷新网盘凭据，过期时提示在 PlutoFish 后台刷新或重新授权；失败可重试或返回根目录，不自动采用旧结果。

115 调度由服务端使用发布端绑定的源账号执行。下载器只取得临时 OSS 凭据，长期网盘 Token 不下发，临时凭据不写入清单。V2 按官方文档使用本次任务的完整 endpoint，不重复拼接 bucket。2026-10-15 实测旧版调度仍可能返回空 file_id 且缺少 endpoint；此时先保存 pick_code，再从临时凭据读取 OSS 区域地址，由 SDK 按区域地址拼接 bucket，不写死上传主机。分片初始化携带 sequential，之后串行发送，以便 115 的合并回调读取完整 SHA1。保留原 pick_code/uploadId，通过 ListParts 核对分片并校验 Content-MD5/ETag；Complete 的 HTTP 200 还须检查回调 state，最终仍由服务端核验文件身份；令牌接近过期或超过 60 秒时刷新凭据/速率。`transfer_config.rate` 换算为 OSS bits/s 限速，同一网盘用户由服务端占用锁串行上传，20 秒续约，失联 240 秒后释放；这不协调 PlutoFish 外部客户端的上传流量。

Complete 回执丢失时先按原任务核验网盘文件大小和 SHA1。115 的原上传任务码可能不同于完成文件取件码；服务端仅从任务绑定目录中核对唯一同名、同大小、同 SHA1 的完整文件，再通过真实取件码复核，返回独立的 filePickCode 供资源登记，不改用于续传的 pickCode。仅针对旧版未启用 sequential 的已合并断点：服务端明确返回文件尚未就绪、且 OSS 明确返回 NoSuchUpload 时，保留旧 uploadId 供追溯，沿用原 pick_code/object 创建顺序分片会话；普通网络故障和核验错误不能触发迁移。目录登记失败可以单独重试，不重复上传成品；最终登记为草稿版本，绝不自动发布。当前完成链只处理任务的主视频文件，独立外挂字幕仍走原文件上报契约。

协议依据：[115 上传流程](https://open.115.com/doc/115开放平台/API列表/文件管理/文件上传/上传流程.md?raw=true)、[获取上传凭证](https://open.115.com/doc/115开放平台/API列表/文件管理/文件上传/获取上传凭证.md?raw=true)、[文件上传](https://open.115.com/doc/115开放平台/API列表/文件管理/文件上传/文件上传.md?raw=true)、[断点续传](https://open.115.com/doc/115开放平台/API列表/文件管理/文件上传/断点续传.md?raw=true)（2026-10-15 读取，文档最后修改于 2026-09-14），以及 [ali-oss SDK](https://github.com/ali-sdk/ali-oss) 和 [OpenList 的 115 顺序分片实现](https://github.com/OpenListTeam/OpenList/blob/main/drivers/115_open/upload.go)。
