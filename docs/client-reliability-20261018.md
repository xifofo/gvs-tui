# 下载可靠性与桌面兼容修复（2026-10-18）

本次改动基于 main 的 `577b5de`，集中处理国内版爱奇艺批量分片地址失效、IQ 跨集音轨 ID 变化、macOS DDP 校验兼容和同平台节目 ID 别名下的历史状态识别。

## 国内版爱奇艺分片取址

旧实现遇到 `refresh=1` 时删除整个 plan 的缓存，一个线程刷新单片地址就会使其他线程刚取得的批量地址失效。现在只清除当前 index，并合并响应中的相关分片；排队前后均检查其他线程是否已取得新地址，避免重复刷新同一批。

缓存按网关连接、账号和 plan 隔离，使用逐条 60 秒 TTL，并限制 plan 和分片总数。读取缓存或收到同一个签名地址不会续期，不延长 CDN 地址本身的有效期。已经释放的 plan 不会被晚到的响应重新加入缓存。下载前仍核对 index、字节数和地址数量。

计划中携带的初始地址失效后，后续线程优先使用新取得的批量缓存。首次失败及恢复日志只记录分片编号、来源、固定原因码和取址次数，便于区分 HTTP 拒绝、超时和内容异常，不输出签名地址或票据。

允许在原有 HTTPS `*.ptqy.gitv.tv` 范围内跟随有限次数的调度跳转，每一跳重新校验域名、协议、循环和次数，保留响应大小检查及取消能力。国内版媒体请求继续走原有直连传输。

另支持视频明确为 `drmType=1`、local-v1 版本和身份完整但 ticket 为空的明文分片。未知或受保护类型仍要求完整处理材料。

这项改动减少重复取址，并不保证固定下载速度：CDN、网关往返时间和签名有效期仍会影响吞吐。它也不能修复网关缺失的尾段映射或下载器尚不支持的分片格式。

## IQ 音轨身份与语言

批量下载不再把探测集的音轨 ID 直接用于所有分集。先验证当前集目录：优先精确匹配；ID 变化时，仅允许唯一、语言和编码/档位一致的候选，并保留手动默认音轨。缺失、歧义或语言不符时在下载视频前停止，重取流后再次核验。独立音轨响应也需与已确认的候选一致。

纠正 IQ 海外版音频语言 ID 5（韩语）、6（日语）和 157（泰语）的已知误标。对于确认有误的单语言目录，允许平台片名中的明确配音版说明（例如“中文版”）纠正标签；保留真实多语言目录和明确日语音轨。国内版和海外版的语言 ID 分开处理，不用作品的制作地区推断实际配音。

## macOS DDP 验收兼容

少量 E-AC-3 文件的开头会触发 FFmpeg 软件解码器的特定 exponent / spectral extension 诊断，而 macOS AudioToolbox 可以正常解码。仅在 macOS 出现已知诊断时进行额外复核：

- 完整 CRC 检查，输出必须正常结束且有有效时长；只允许限定次数的已知诊断。
- 按流确认音频编码，仅对 E-AC-3 选择 `eac3_at`，同文件中的 AAC 保持自己的解码器。
- AudioToolbox 完整解码必须正常结束，禁止系统解码错误，复核时长差不超过 100 ms。
- 读取时间戳仍要求有效媒体包、成功退出且没有诊断溢出。

CRC 错误、截断、其他解码错误、反复出现的故障、无有效包或取消操作仍会失败。兼容路径仅用于验收，不重编码、不丢弃开头音频包。

## 桌面端与诊断

- 下载历史查询支持当前分集 VID 列表，在同平台节目 ID 变化时找回已下载状态；跨节目匹配必须命中 VID，不靠相同集号推断。长列表分批绑定查询，过时页面请求不会覆盖新状态。
- 已安装桌面版优先使用包内受管理下载器，避免旧用户缓存遮蔽更新；缺失时的下载器版本更新至 IQ.3。FFmpeg 等可写工具包装路径保持原有用途。
- 下载器明确报告不支持的 IQ 分片格式时，保留兼容性错误并停止无效 CDN 重试；并发 HTTP 错误不再覆盖根因。
- friDay、LINE TV 的隧道源站请求支持已配置或系统 HTTP/HTTPS 代理。IQ 目录改写只作用于 IQ；国内平台媒体请求不扩展到这个代理路径。
- macOS 使用单独生成的图标资源，修正重复缩进造成的 Dock 图标过小，Windows 图标不变。

## 验证

本地验证环境为 macOS arm64、Bun 1.3.14、Node 24.19.0、Go 1.24.13、FFmpeg 9.0.1。

- IQ 音轨/语言、国内版取址缓存和预取、错误分类、工具路径、代理路由、历史状态：Bun 运行 10 个测试文件，92 通过、0 失败。
- IQ 实际封装、国内版实际 helper/封装、CDN 跳转、下载器进程与进度：Node 运行同一批 Bun 测试源的 4 个文件，61 通过、0 失败。
- E-AC-3、时间戳、MKV、腾讯成片与音轨排序相关回归：42 通过，2 个需要媒体环境的用例随后在集成组执行；媒体集成组 14 通过、0 失败。
- `tools/iqcn-local` 的 `go test ./...` 通过。
- TUI `tsc --noEmit`、桌面 renderer `vue-tsc --noEmit -p tsconfig.web.json`、桌面 main `tsc --noEmit -p tsconfig.node.json` 通过。

本机 Bun 的子进程输出读取存在异常，含 FFmpeg/helper 的测试在 Bun 下会读到空输出；上述 61 项及 E-AC-3 媒体验证通过临时 `bun:test` 断言适配器在 Node 下执行。适配器只替换测试框架入口和 `Bun.sleep`，生产源码直接执行，没有模拟媒体命令成功。92 项不依赖该适配器。
